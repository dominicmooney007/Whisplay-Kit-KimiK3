Raspberry Pi 5 + Whisplay HAT
An interactive guide — every command explained, every command copyable.

How to use this guide: work through the steps in order. Press Copy on any code block to grab just the commands (never the example output), paste them into your Pi's terminal, then open “Explain these commands” to understand what you just ran. Tick Step complete as you go — your progress is saved in this browser.

STEP 1 Prepare your kit

Goal: have everything on the table before you start.

  • 🥧 Raspberry Pi 5 (any RAM size) with the 40-pin header
  • 🍬 PiSugar Whisplay HAT (1.69″ 240×280 LCD, button, RGB LED, dual mics, 1 W speaker)
  • 💾 microSD card, 16 GB or larger
  • ⚡ Official 5 V / 5 A USB-C power supply
  • 💻 A laptop/PC with a microSD reader, and either an HDMI monitor + USB keyboard for the Pi or an SSH connection
Handle with care
  • The Whisplay screen is glass. Hold the HAT by its PCB edges — never press on the display.
  • Always fit or remove the HAT with the Pi powered off.
  • If you also use a PiSugar battery board, flip its AUTO switch off: it shares the I2C bus and can stop the audio chip from being detected.

STEP 2 Flash Raspberry Pi OS “Trixie”

Goal: a fresh, up-to-date OS on the microSD card, with SSH enabled if you need it.

  1. On your laptop, open Raspberry Pi Imager (install it from raspberrypi.com/software if needed).
  2. Choose Device: Raspberry Pi 5.
  3. Choose OS: Raspberry Pi OS (64-bit) — this is the “Trixie” (Debian 13) release.
  4. Choose Storage: your microSD card. Double-check you picked the right drive — it will be erased!
  5. Click Next → Edit Settings and set:
    • hostname, e.g. whisplay, plus a username and password
    • your Wi-Fi name and password
    • Enable SSH (on the Services tab) if you'll work without a monitor
  6. Write the card, then move it into the Pi.
💡 What those settings did: the Imager writes first-boot config files onto the SD card (user account, Wi-Fi credentials, an ssh flag file). The Pi applies them on its very first boot, so you never need to set them up by hand.

STEP 3 Mount the HAT & first boot

Goal: Whisplay physically connected and a terminal open.

  1. With the Pi unpowered, press the Whisplay onto the 40-pin header. Orient it so the button sits above the USB/Ethernet end of the Pi 5. All 40 pins should be covered; hold the board edges, not the glass.
  2. Peel the protective film off the screen.
  3. Connect power. First boot takes ~1 minute; the Pi may reboot once while it expands the filesystem.
  4. Open a terminal: on the desktop use the terminal icon (or Ctrl+Alt+T); over the network use SSH from your laptop:
terminal (your laptop, for SSH)
ssh yourname@whisplay.local
Explain this command
ssh …Secure Shell — runs a terminal on the Pi over the network.
yourname@The username you set in the Imager.
whisplay.localThe Pi's hostname. .local (mDNS) finds it on your network without knowing its IP. If it fails, find the IP in your router and use ssh yourname@192.168.x.x.
💡 Everything from here runs in this terminal on the Pi.

STEP 4 Update the system

Goal: latest packages and kernel — this matters for the Pi 5 GPIO fix described below.

terminal
sudo apt update
sudo apt full-upgrade -y
Explain these commands
sudo“Superuser do” — run the command with administrator rights. Installing software and enabling hardware buses need this.
apt updateRefreshes the list of available packages from Debian/Raspberry Pi servers. It installs nothing.
apt full-upgrade -yDownloads and installs the newest versions of everything, allowed to add/remove dependencies. -y answers “yes” to prompts so it runs unattended. First run can take a few minutes.
Why the Pi 5 cares: the kernel update includes the change that exposes the Pi 5's header GPIO as gpiochip0 (alias of the pinctrl-rp1 controller). whisplay-kit detects it automatically either way.
terminal
sudo reboot

Reboot so the new kernel is active, then reconnect / reopen your terminal.

STEP 5 Install the official Whisplay driver

Goal: kernel-level support for the screen and the sound chip.

terminal
cd ~
git clone https://github.com/PiSugar/Whisplay.git --depth 1
cd Whisplay
sudo bash install_driver.sh
sudo reboot
Explain these commands — and what the installer actually does
cd ~Go to your home directory so the download lands somewhere tidy.
git clone … --depth 1git downloads the driver's source repository from GitHub. --depth 1 fetches only the latest snapshot (no history) — faster.
sudo bash install_driver.shRuns PiSugar's installer as administrator. It:
  • Detects your platform (Raspberry Pi) and OS.
  • Enables the SPI bus (talks to the LCD) and the I2C + I2S buses (talk to the audio chip) in the boot configuration.
  • Installs the whisplay-soundcard device-tree overlay — the piece that teaches the Linux kernel that an ES8389/WM8960 audio chip exists, so it appears as a real sound card.
  • Programs ALSA (Linux's sound system) defaults for speaker and microphones.
sudo rebootBus and overlay changes only take effect at boot.
EEPROM magic: the Whisplay HAT carries a tiny ID chip. On boot the Pi 5 reads it and loads the sound overlay by itself — that's why after this one-time install, everything “just works” on every boot.
If the sound card doesn't appear after reboot
Old driver versions (install_wm8960_drive.sh) are deprecated — always use the unified install_driver.sh from a fresh clone. Also make sure no other HAT (or a PiSugar battery in AUTO mode) is occupying the I2C bus.

STEP 6 Verify the hardware

Goal: prove each peripheral exists before writing any code.

6.1 — Sound card

terminal
aplay -l
arecord -l
Expected output
card 0: whisplaysound [Whisplay Sound], device 0: Whisplay HiFi ES8389 HiFi-0 [...]

Both commands must list whisplaysound. aplay -l shows playback (speaker); arecord -l shows capture (microphones).

Explain these commands
aplay -lALSA (Advanced Linux Sound Architecture) tool: -l lists all playback devices the kernel knows.
arecord -lSame, but for recording (capture) devices.

6.2 — Play a test tone through the speaker

terminal
amixer -c whisplaysound cset name=speaker 80
speaker-test -D plughw:whisplaysound,0 -t sine -f 440 -l 1
Explain these commands
amixer -c whisplaysound cset name=speaker 80 amixer talks to the card's mixer. -c whisplaysound selects the card by name (safer than the number, which can change between boots), and this sets the speaker control to 80 (of 100).
speaker-test -D plughw:… -t sine -f 440 -l 1 Plays a 440 Hz sine wave (“concert A”) once (-l 1). -D plughw:whisplaysound,0 chooses the device; the plug prefix means ALSA automatically converts the audio format to what the chip wants.

🔊 You should hear a clean beep. Very quiet? Raise the number to ~90; above ~100 the driver clamps at 100 and the small speaker distorts anyway.

6.3 — Record and play back the microphones

terminal
amixer -c whisplaysound cset name=mic 60
arecord -D plughw:whisplaysound,0 -f S32_LE -r 16000 -c 2 -d 3 memo.wav
aplay -D plughw:whisplaysound,0 memo.wav
Explain these commands
name=mic 60Mic pre-amp gain 60/100. If recordings are too quiet, raise it.
-f S32_LESample format: signed 32-bit little-endian samples. That's the format Whisplay's codec driver prefers (plughw would convert others anyway).
-r 16000 -c 2 -d 316 kHz sample rate (fine for speech), 2 channels (the board has two mics: left + right), record for 3 seconds.
memo.wavOutput file — a standard WAV you can play anywhere.

6.4 — SPI (screen bus) and GPIO chip

terminal
ls /dev/spidev*
gpiodetect
Expected output
/dev/spidev0.0  /dev/spidev0.1
gpiochip0 [pinctrl-rp1] (54 lines)
gpiochip10 [gpio-brcmstb@…] (32 lines)
…
Explain these commands
ls /dev/spidev*SPI devices appear as files under /dev. spidev0.0 is the bus the LCD hangs on; if it's missing, SPI wasn't enabled.
gpiodetectLists all GPIO controller chips. On a current Trixie kernel the Pi 5's header pins live on gpiochip0 [pinctrl-rp1] (54 lines). On older kernels this same controller was called gpiochip4 — which is exactly why whisplay-kit finds it by name instead of a fixed number.
✅ All checks green? The hardware layer is ready. The screen won't show anything yet — it lights up in step 8 when our Python code first talks to it.

STEP 7 Install the Python pieces & whisplay-kit

Goal: the friendly Python API on top of the hardware.

7.1 — System libraries

terminal
sudo apt install -y python3-spidev python3-libgpiod python3-pil python3-venv python3-pip
sudo apt install -y python3-numpy mpg123 ffmpeg
Explain what each package gives you
python3-spidevLets Python push bytes over SPI — that's how we send pixels to the LCD (at up to 100 MHz!).
python3-libgpiodThe official way to control GPIO pins from Python on modern Linux. Trixie ships version 2.2 — whisplay-kit speaks both v1 and v2.
python3-pilPillow, the image library. All screen drawing (text, shapes, photos) is Pillow work.
python3-venv / -pipTools for virtual environments and package installs.
python3-numpyOptional: makes whole-screen refresh roughly 2× faster.
mpg123 / ffmpegOptional: lets speaker.play() handle MP3 and other formats (WAV works without them).

7.2 — Get whisplay-kit onto the Pi

terminal
cd ~
# Option A: you already copied the whisplay-kit folder to the Pi (USB stick / scp) — just cd into it.
cd ~/whisplay-kit
# Option B: fetch it with git instead:
# git clone <your-whisplaykit-repo-url> whisplay-kit && cd whisplay-kit

7.3 — Create a virtual environment and install

terminal
python3 -m venv --system-site-packages ~/whisplay-venv
source ~/whisplay-venv/bin/activate
pip install .
Explain these commands — and why Trixie needs a venv
python3 -m venv …Creates a private Python environment in ~/whisplay-venv. Trixie's system Python is “externally managed” (PEP 668): pip install into it directly is refused, to protect apt-managed packages. A venv is the clean workaround.
--system-site-packagesImportant! The venv can still see apt-installed packages (spidev, gpiod, Pillow). Those don't exist on PyPI in reliable form, so a sealed venv couldn't use the hardware.
source …/bin/activateSwitches this terminal into the venv — the prompt gains a (whisplay-venv) prefix. Do this in every new terminal before running examples.
pip install .Installs the package described by the current folder (.) — i.e. whisplay-kit itself, plus its dependency Pillow.
Shortcut for impatient people: pip install . --break-system-packages skips the venv entirely. It works because whisplay-kit is tiny and pure-Python, but the venv habit will save you on every bigger project.

STEP 8 Run the demos

Goal: see every peripheral working under our API.

terminal (in ~/whisplay-kit, venv active)
python3 examples/01_hello_display.py
python3 examples/02_rgb_led.py
python3 examples/03_button_events.py
python3 examples/04_voice_memo.py
What each demo does
01_hello_display.pyDraws text, shapes and a progress bar to the LCD, then dims the backlight. One buffered frame → one SPI push.
02_rgb_led.pyTours solid colours, blinking, a breathing “pulse”, and a rainbow — all background-thread effects.
03_button_events.pyTap = green flash, double-tap = cyan, long-press exits. Shows the gesture engine (debounce + click/double/long).
04_voice_memo.pyThe full loop: hold the button to record (red LED + timer on screen), release to hear it back (green LED). Long-press exits.

Exit any demo with Ctrl+C. If a demo can't open GPIO/SPI: sudo usermod -aG gpio,spi $USER and re-login (adds your user to the hardware groups).

Using the optional whisplay-daemon?
The official whisplay-daemon service owns the LCD/LED/button. whisplay-kit talks to the hardware directly, so stop the daemon first: sudo systemctl stop whisplay-daemon (and sudo systemctl disable whisplay-daemon if you want that permanently).

STEP 9 Your first program

Goal: understand the 9-line core pattern every Whisplay app shares.

terminal
nano myapp.py

Paste this into nano (copy with the button), save with Ctrl+O, Enter, exit Ctrl+X:

python — myapp.py
from whisplaykit import Whisplay        # 1

with Whisplay() as board:                # 2
    board.display.fill("#101830")        # 3
    board.display.text_centered("TAP ME", 60, size=26, bold=True)  # 4
    board.display.refresh()              # 5

    board.led.pulse("navy", period=2.5)  # 6

    def tapped():                        # 7
        board.speaker.beep(880)
        board.led.blink("green", times=2)

    board.button.on_click(tapped)        # 8
    board.button.wait_for_long_press()   # 9
terminal
python3 myapp.py
Line-by-line: what your program does
1Imports the Whisplay class — one object controlling the whole board.
2with … as board opens the hardware: SPI, the GPIO lines (found automatically, incl. the Pi 5's gpiochip0), and a background thread watching the button. Leaving the with block cleans everything up automatically.
3–4Drawing goes to an off-screen buffer: fill dark navy, then centred bold text at y=60. refresh() (line 5) pushes the buffer to the LCD in one transfer — nothing appears before it.
6A breathing navy glow — runs in the background while your code continues.
7–8on_click registers a callback: the button thread calls tapped() each time you tap. It beeps at 880 Hz and flashes green.
9Blocks until you hold the button (~0.8 s) — this is our “quit gesture”. Then the with block closes: LED off, pins released, done.
Try next: make the tap counter show on screen (board.display.clear() → text_centered(f"Taps: {n}", 130) → refresh() inside tapped()), or change the breathing colour. Prototype live: run python3 alone and type these commands interactively!

Troubleshooting quick accordion

No sound / aplay -l lacks whisplaysound
Reboot after the driver install; turn a PiSugar battery's AUTO switch off; re-run sudo bash install_driver.sh from a fresh clone; check dmesg | grep -i es8389.
Screen stays black
Confirm ls /dev/spidev* exists (driver step). Our code sets the backlight on init — try board.set_brightness(100). The glass is fragile; a physically cracked panel shows streaks or nothing.
pip install says “externally-managed-environment”
That's Trixie protecting itself. Use the venv from step 7.3, or append --break-system-packages.
GPIO permission errors in Python
sudo usermod -aG gpio,spi $USER, then log out/in. Or run with sudo -E python3 … while experimenting (-E keeps your venv).
MP3 won't play
sudo apt install mpg123 (or ffmpeg). WAV always works.
Button/LCD seems “taken” by another process
The official daemon owns the hardware when running: sudo systemctl stop whisplay-daemon.
